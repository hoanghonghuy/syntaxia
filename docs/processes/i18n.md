# i18n parity (en / vi)

## Purpose

Keep UI locale files and SQL Fundamentals lesson pairs in sync so English and Vietnamese never drift.

## When to use

- After adding or renaming any `t('…')` key
- After adding/removing curriculum lesson markdown under `docs/curriculum/`
- Before marking product-perfection checklist **#7** (or re-running the gate)
- During `/opsx-verify` when UI copy changed

## Steps

1. Edit strings in **both** `apps/web/i18n/locales/en.json` and `vi.json` with the same key tree.
2. Prefer `t('namespace.key')` in Vue; do not leave user-facing English/Vietnamese hardcoded in templates.
3. For SQL Fundamentals lessons, keep matching slug filenames under `docs/curriculum/sql-fundamentals/en/` and `…/vi/`.
4. Run the parity test from `apps/web`:

```bash
npm run test:i18n
```

5. Fix any `onlyEn` / `onlyVi` key lists or lesson slug mismatches the test prints.

## Do

- Add new keys to **en and vi in the same change**
- Keep technical identifiers (`en`/`vi` locale codes, SQL snippets, brand “Syntaxia”) as-is when they are not prose
- Re-run `npm run test:i18n` after locale or curriculum file changes

## Don't

- Add a key to only one locale file
- Invent lesson outlines; curriculum content stays mapped from public sources (see product baseline)
- Rely on chat memory for missing keys — the script is the gate
