Ứng dụng thường cần giá trị được tạo ra bởi write: id tự sinh, default, giá trị bị trigger điều chỉnh hoặc chính hàng vừa thay đổi. PostgreSQL có thể trả chúng từ cùng mutation.

## Mô hình tư duy

Không có `RETURNING`:

```text
INSERT -> thành công -> chạy SELECT khác để tìm generated value
```

Có `RETURNING`:

```text
INSERT -> PostgreSQL ghi hàng -> cùng statement trả các cột yêu cầu
```

RETURNING list hoạt động giống SELECT output list trên các hàng bị mutation tác động.

## Dự đoán trước khi chạy

Id 1 và 2 đã tồn tại. Identity sinh id 3 cho Dune, nên kết quả trả về phải là một hàng `(3, 'Dune')`.

## Ví dụ mẫu

```sql
INSERT INTO movies (title)
VALUES ('Dune')
RETURNING id, title;
```

| id | title |
| ---: | --- |
| 3 | Dune |

Cách này tránh một lần read riêng chỉ để tìm generated id. `RETURNING` cũng dùng được với UPDATE, DELETE và PostgreSQL hiện đại hỗ trợ cả MERGE.

## Tìm lỗi

```sql
INSERT INTO movies (title) VALUES ('Dune');
SELECT id, title FROM movies WHERE title = 'Dune';
```

Có thể chạy đúng nhưng statement thứ hai tạo thêm round trip và còn cần cách nhận diện chắc chắn đúng hàng vừa ghi. Khi cần chính changed row, RETURNING biểu đạt intent trực tiếp hơn.

## Lỗi thường gặp

- Nghĩ RETURNING chạy trước mutation; nó báo các hàng thực tế bị tác động.
- Dùng query thứ hai không cần thiết để lấy generated value.
- Luôn `RETURNING *` dù application chỉ cần vài cột.

## Thử ngay

Insert Dune và trả generated `id` cùng `title` từ chính statement đó.

## Tự kiểm tra

`RETURNING id` giải quyết vấn đề thực tế gì sau INSERT có identity tự sinh?

**Đáp án:** nó trả generated id trực tiếp từ write, không cần query tìm lại.
