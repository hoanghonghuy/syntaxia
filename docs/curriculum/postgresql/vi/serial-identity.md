PostgreSQL có thể tự sinh key. Trong schema hiện đại, `GENERATED ... AS IDENTITY` thể hiện intent này trực tiếp và gắn một implicit sequence phía sau cột.

## Mô hình tư duy

```sql
CREATE TABLE movies (
  id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  title TEXT
);
```

Luồng ghi:

```text
INSERT chỉ title -> identity sequence cấp id tiếp theo -> lưu hàng
```

Khi id 1 và 2 đã tồn tại, bỏ `id` ở lần insert sau sẽ tạo id 3.

`SERIAL` là shorthand PostgreSQL cũ cũng tạo hành vi auto-number dựa trên sequence. Cần nhận ra nó trong database cũ, nhưng khi thiết kế schema mới nên ưu tiên identity column trừ khi project có constraint khác.

## Dự đoán trước khi chạy

Id sinh tiếp theo là 3. Dự đoán toàn bộ bảng sau khi chỉ insert title `Dune`.

## Ví dụ mẫu

```sql
INSERT INTO movies (title)
VALUES ('Dune');
```

| id | title |
| ---: | --- |
| 1 | Inception |
| 2 | The Matrix |
| 3 | Dune |

## Tìm lỗi

```sql
INSERT INTO movies (id, title)
VALUES (3, 'Dune');
```

Với `BY DEFAULT` câu này có thể được chấp nhận, nhưng nó đi ngược mục tiêu bài và dễ tạo vấn đề quản lý sequence/key nếu explicit id được dùng tùy tiện. Bình thường hãy để identity cấp id.

## Lỗi thường gặp

- Nghĩ application luôn phải tự tính id được sinh.
- Chỉ học `SERIAL` và bỏ lỡ identity syntax rõ nghĩa trong PostgreSQL hiện đại.
- Nghĩ id tự sinh tự nó đảm bảo mọi uniqueness nghiệp vụ; integrity vẫn do key/constraint định nghĩa.

## Thử ngay

Insert Dune mà không cung cấp `id`, rồi verify PostgreSQL sinh id 3.

## Tự kiểm tra

Khi khai báo key tự sinh trong schema hiện đại, cách nào rõ nghĩa hơn: `IDENTITY` hay `SERIAL`?

**Đáp án:** `GENERATED ... AS IDENTITY`; `SERIAL` vẫn là shorthand cũ cần nhận biết.
